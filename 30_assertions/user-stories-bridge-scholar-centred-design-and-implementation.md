# User stories translate scholarly practice into narrative scenarios that stand beside the formal requirements

## Statement

A user story names a role, a goal, and a benefit, arises typically in the Preparation or Exploration phase from sessions with domain experts, and is refined iteratively. The formal counterpart of the same matter is a recorded expectation of the system in checkable language with an acceptance criterion, numbered as a functional or non-functional requirement.
