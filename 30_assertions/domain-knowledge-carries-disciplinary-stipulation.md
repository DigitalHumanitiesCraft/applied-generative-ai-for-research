# A domain-knowledge document carries a disciplinary stipulation that follows neither from the material nor from a software requirement

## Statement

The function carries as soon as a project makes a rule, a mapping, a calculation logic, a vocabulary, or a theoretical framing that a domain expert answers for and that has to be known in order to interpret or extend the output correctly. It separates a reasoning layer carrying theoretical framework, research questions, and methodological decisions from a rule set carrying the normative detail of annotation, mapping, and calculation, and the two are split into separate files once they develop their own update rhythms and reader groups. A coding agent reads the rule set before it generates annotation or calculation code, so a vague rule layer produces annotations that miss the intended semantics.
